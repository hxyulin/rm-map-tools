# RMUC 2026 assets, 11 September 2026

This release replaces `field-elements-v1.2.0-r1` with corrected CAD assemblies, the optimized field package, articulated equipment exports, and the interactive documentation models. The previous release's individual files are obsolete and have been removed to avoid retaining duplicate downloads.

## What changed since the old release

- Corrected source ownership and recovered sheet geometry. The old STEP attachments omitted sheets; the replacement assemblies include the corrected source bodies.
- Kept the Outpost footing separate from its main body, preserving their source placements.
- Applied configurable tessellation and checked mesh simplification to the retained GLB runtime, with separate visual and collision settings and component preservation.
- Converted selected artwork to native glTF textures, repaired configured backing surfaces, and removed explicitly reviewed decoration colliders.
- Removed two duplicate road wordmarks beneath the grafted roads while retaining the other markings and terrain.
- Extracted six resource-zone energy units as separate instances sharing their mesh files.
- Added SDF/URDF/USD equipment exports using the existing semantic joint hierarchy.
- Replaced recorded videos with an interactive documentation catalog. The viewer can focus on each moving entity and reset it to the CAD rest pose.

## Optimized GLB package

Extract the archive and retain the entire `field/` directory, including `equipment/`, texture images, and JSON sidecars. Consumers should load the package manifest and use its placements, file hashes, and collision declarations.

The package has 14 top-level asset records, including six energy-unit instances. Visual and collision GLBs are separate. Some asset records reference shared files, so do not duplicate or rename meshes when unpacking. Manifest placements use metres; apply each placement once.

This is the optimized runtime package. Its mesh counts and selected decoration colliders differ from the unsimplified semantic reference used to generate the articulated equipment and documentation models. Mesh reduction is checked against input tessellation with sampled distances; it is not a certified maximum error from the original STEP.

## Editable STEP assemblies

The CAD archive contains Base, Outpost, Power Rune, Dart station, resource zone, centre platform, fortress, Technology Core, undulating road, and Outpost footing. Open an individual `.step` in a CAD application; use `manifest.json` for assembly placement and file hashes.

These are source-based STEP assemblies, not meshes converted back into CAD. STEP units are declared within each file; placement metadata uses metres. The archive does not contain a full-map STEP. Obtain the original full assembly through the source downloader.

The retained OCCT report marks all ten assemblies valid with no reported problems. Base and resource-zone face-count deltas are recorded in the manifest. Reconstructed Base interiors, display-rig bearings, texture bakes, and mesh simplification are separate downstream operations and are not additions to these source STEP assemblies.

## Simulator equipment

The simulator archive contains an `rm_map_equipment/` package with one directory per equipment asset:

| Equipment | Movable joints | Motion |
| --- | ---: | --- |
| Base | 4 | Three shields and rail-mounted dart target |
| Power Rune | 2 | Front and rear rotors |
| Outpost | 1 | Rotor and attached hardware |
| Dart station | 1 | Sliding window and carriage |
| Technology Core | 0 | Six fixed reference joint frames, with original joint metadata retained |

Each directory contains `model.sdf`, `model.urdf`, `model.usdc`, and `semantics.json`. SDF/URDF share STL mesh resources; USD embeds geometry. Keep the directory structure intact.

- **SDF:** load the equipment's `model.sdf` through the target simulator's model path. These are individual equipment models, not a complete arena world.
- **URDF:** copy `rm_map_equipment/` into a ROS 2 workspace's `src/`, run `colcon build`, and source `install/setup.bash` so `package://rm_map_equipment/...` resolves. Install one package with that name at a time.
- **USD:** open `model.usdc`. Use the asset-to-arena placement in `semantics.json` when assembling a world. Some source equipment has local Y as its vertical axis; do not rotate source vertices based only on a viewer's up-axis setting.

Joint axes, hierarchy, known travel, and visual/collision membership are retained. Base target travel is ±280 mm. The Dart window follows its 15-degree guides to the 205 mm platform level. Base shields travel 170 mm outward and 45 mm down.

The exports describe kinematics. Mass, inertia, actuators, and match controllers are not authored. URDF effort and velocity values of zero are compatibility fields, not measured limits. Materials preserve base colors; textures and other PBR properties are not converted.

Static MJCF is not included. A fresh static-scene candidate failed MuJoCo's STL decoder because one source collider exceeded 200,000 faces; that unverified candidate is not part of this release.

## Interactive documentation models

The documentation catalog contains the same five mechanism names and 14 controls: eight bound equipment joints plus six Technology Core display-rig axes. The Core's CAD display rig has schematic bearing housings and restored tool enclosure geometry. It is separate from the fixed-frame Core model in the simulator archive.

Models load individually, and each download is checked against its catalog hash. The viewer supports orbiting, zooming, joint sliders, per-joint Focus, and Reset. Local GLB/URDF/SDF file loading remains available.

For a documentation deployment, extract `docs-viewer-models.zip` under `docs/public/`, producing `docs/public/models/catalog.json`. The repository's `DOCS_MODELS_URL` points to this archive so GitHub Pages receives the model catalog during its build.

## Validation and provenance

- Verified 32 runtime visual/collision asset references against manifest hashes.
- Verified all ten STEP files against their recorded hashes and retained successful OCCT validation records. Packaging did not repeat the CAD-kernel imports.
- Verified 967 articulated package file hashes, parsed every SDF/URDF, resolved all XML mesh paths, and opened all five USD stages.
- Tested every catalog joint against actual CAD geometry, including movement and exact rest-pose restoration.
- Verified all five served model downloads after decompression against their catalog hashes.
- Built the documentation site and checked source and generated-page links.

These checks cover files, geometry bindings, and export structure. They do not claim Gazebo/Isaac controller behavior, a ROS workspace build, or dynamic simulation calibration.

The field derives from RMUC2026 V1.2.0, with the reviewed V2.0.0 road grafts. The downloadable validation summary records source STEP and reference-manifest SHA-256 values. Per-package manifests provide the detailed file provenance.
