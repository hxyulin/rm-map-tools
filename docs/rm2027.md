# RoboMaster 2027 sources and asset builds

The 2027 workflow exports the official RMUC V1.0.0 arena, RMUL 3v3 V1.0.0
arena, RMUL 1v1 V1.0.0 arena, and energy unit. Download URLs, byte sizes,
ETags, and SHA-256 hashes are recorded in
[`source/SOURCES.json`](../source/SOURCES.json). The energy unit is stored as
`能量单元2027.stp` so the older `能量单元.stp` remains available.

## Rebuild the release archives

Install the [CAD environment](getting-started.md#install-the-cad-environment)
and the additional export dependencies:

```sh
cargo build --release --locked
uv pip install --python ocpenv/bin/python usd-core
uv pip install --python ocpenv/bin/python -r python/requirements-simplification.txt
OPENBLAS_NUM_THREADS=1 ocpenv/bin/python scripts/build_2027_release.py --prepare
```

The build writes four archives, `SHA256SUMS.txt`, and
`validation-summary.json` under `out/rm2027/release/`:

- `rm2027-cad-step.zip`: source-based STEP assemblies and exact placements.
- `rm2027-glb-optimized.zip`: component visuals, collision meshes, complete
  arenas, semantic descriptors, and mesh reduction reports.
- `rm2027-simulators.zip`: SDF, URDF, and USD models with shared STL resources,
  manifests, source placements, and source ownership notices.
- `docs-viewer-models.zip`: a combined `models/catalog.json` and compressed
  models for all four sources, using the existing documentation viewer format.

Each archive groups its contents by source (`rmuc2027`, `rmul2027-3v3`,
`rmul2027-1v1`, and `energy-unit2027`). In the CAD and GLB archives, paths
are compatible: extracting both into one directory supplies the `cad/` files
referenced by the GLB manifests. In the simulator archive, each source has its
own `rm_map_equipment` ROS package; install one package of that name at a time.
Use the placement matrices in its `semantics.json` files to assemble the arena.

The source packages and mesh caches remain under `out/rm2027/`. Complete
packages are verified and reused on subsequent builds. Select fresh
`--work-dir` and `--out` paths after changing export policy. Failed builds keep
their logs and staging geometry for diagnosis; they are not marked complete.
The script generates local release artifacts and does not publish to GitHub.

## Source structure and parser compatibility

RMUC has 49 products, 84 assembly occurrences, and 426 unique geometry bodies.
Creo gives several products the same opaque name, such as `001_ASM`.
[`rules/sources-2027.json`](../rules/sources-2027.json) pins the source hashes
and assigns names by product entity ID. Top-level occurrence descriptions
identify the floor, central high ground, red and blue ramp/dart-station
assemblies, roads, resource zones, fortresses, base footings, fan frames,
fans, and bases. Each source branch is retained rather than matched to a
2026 assembly with a similar name.

The RMUL files each have one product containing a solid and a surface body.
Their surface body is referenced by both its geometric representation and
a property-only representation. Both the Rust and Python parsers count that
body once and retain its product-linked owner. This prevents the property
reference from overwriting ownership or duplicating the body in reports.

Root occurrence paths define full-map membership. A fan nested inside a ramp
stays with that ramp; directly placed fans form a separate asset. The build
compares occurrence counts against the complete source tree, including shared
products, before exporting. It rejects unowned bodies and missing or duplicate
placements. Solids, sheets, source colors, and source transformations are retained.

## Coordinates, fidelity, and motion

RMUC uses Z-up source coordinates, the RMUL arenas use negative-Y-up, and the
standalone energy unit uses positive-Y-up. Component STEP and GLB files retain their source axes and are
recentered near their geometry. Placements convert millimetres to metres and
rotate the declared source up vector into the right-handed Z-up arena frame. Apply each placement
once. The full-map GLBs already include those placements. Viewer catalog entries
declare the appropriate up vector for each component and full map.

Every generated STEP assembly is read back through OCCT. Its solid and face
counts are compared with imports of its source products, and its mesh bounds
must agree with the component GLB within 5 mm. The manifest records these
checks, including any source-reader healing effects. The GLBs use the existing
`simulation` tessellation policy, with independent collision tessellation.

The optimized archive applies the existing meshoptimizer pipeline with locked
borders, component preservation, a 1 mm simplification error setting, and a
2 mm sampled deviation limit using 512 samples per direction. Full maps are
recomposed from the optimized components. These are checks against tessellated
input, not certified maximum deviations from the original CAD. Simulator and
viewer archives retain the unsimplified source-rest-pose tessellation.

These models describe the **2027 CAD rest pose**. The 2026 movable-joint
bindings, travel limits, reconstructed interiors, artwork selections, and road
grafts are not transferred. Mechanical motion needs new source-specific body
selections and evidence before joint controls can be added. SDF/URDF/USD exports
therefore contain fixed single-link assemblies; no dynamics, actuators, or
match controllers are authored.

Release verification checks file hashes, geometry and body coverage, semantic
bindings, XML structure and mesh paths, USD stage opening, viewer decompression
hashes, and ZIP integrity. Simulator runtime behavior and competition accuracy
are outside those checks. CAD ownership remains with DJI / RoboMaster; see
[NOTICE.md](../NOTICE.md).
